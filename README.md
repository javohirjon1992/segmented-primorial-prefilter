# Segmented Primorial Prefilter

Code, data, and analysis scripts for the paper

> I. Ergashev, B. Mamaraimov, I. Boykuziev, B. Abdurakhimov, and J. Abdurazzokov,
> **"Segmented Primorial Prefiltering and Cost-Optimal Sieving Bounds for Prime Generation."**

The method groups the odd primes up to a bound *B* into segments whose sizes grow geometrically
(*s*<sub>0</sub> = 5, *r* = 2) and rejects a candidate as soon as its GCD with a segment product exceeds one.
For candidates larger than the largest sieving prime it rejects exactly the candidates rejected by trial division
over the same primes (Lemma 1), but its cost grows so slowly with *B* that much larger bounds become
cost-effective. The version of this repository used in the paper is tagged `v1.0`.

## Repository layout

```
spp/                    C++17 library (GMP): prefilter, Miller-Rabin, generators, command-line tools, unit tests
experiments/cpp/        experiment programs, run_all.sh, system_info.sh, ctgrind/ (compiled-code analysis)
experiments/python/     Python prototype (CPython integers and gmpy2)
analysis/               scripts that aggregate raw results and recompute every derived quantity of the paper
data/tables/            aggregated results (CSV) underlying all tables and figures
data/raw/               raw outputs: replicated counts, 22,860 provable primes, complete generators, Valgrind logs
figures/                make_figures.py (Figs. 2-7 from data/tables) and workflow_diagram.tex (Fig. 1)
docs/                   REPRODUCE.md (commands and seeds for every table and figure) and experiment protocols
```

## Requirements

* C++17 compiler (GCC 13 or later, or Clang 18), GMP 6.x, OpenSSL 3.x (`libcrypto`) for the OpenSSL experiments,
  `make`; CMake is optional for the library; Valgrind for the compiled-code audit.
* Python 3.9+ with NumPy and Matplotlib for `analysis/derive_paper_numbers.py` and `figures/make_figures.py`;
  pandas and SciPy for the other analysis scripts; gmpy2 (optional) and Jupyter for the prototype
  (`pip install -r requirements.txt`).

Linux (Debian/Ubuntu): `sudo apt install g++ make libgmp-dev libssl-dev valgrind`.
Windows: MSYS2 UCRT64 with `mingw-w64-ucrt-x86_64-{gcc,gmp,openssl}` and `make`.

## Quick start

```bash
cd spp && make && make test && cd ..       # library, tools, unit tests (174,662 checks)
cd experiments/cpp && make
./system_info.sh                            # hardware and software parameters of this platform
./run_all.sh quick                          # 2-3 minute smoke test of all experiment steps
./run_all.sh                                # full run with the settings of the paper (40-70 min on a laptop)
./run_all.sh replicate                      # replicated counts, 22,860 provable primes, complete generators (1-2 h)
./run_all.sh audit                          # ctgrind analysis of the compiled constant-time code (Valgrind; ~30 min)
cd ../..
python3 analysis/derive_paper_numbers.py    # Table 2, ablation, best bounds, OpenSSL statistics, r_C bound
python3 analysis/replication_analysis.py    # replicated counts, provable primes, complete generators (Table 14)
python3 analysis/ctgrind_summary.py         # code locations of Table 4 from the Valgrind logs
python3 figures/make_figures.py             # Figs. 2-7 -> figures/out/*.pdf
```

`docs/REPRODUCE.md` lists, for every table and figure, the exact commands, the seeds, and the resulting files.
`spp/README.md` describes the library API and its command-line tools; `spp_bench <bits> 4000 --sweep`
calibrates the sieving bound on a new platform. GitHub Actions (`.github/workflows/ci.yml`) builds everything,
runs the tests, and regenerates the derived numbers and figures on every push; the ctgrind analysis runs on demand.

## Reproducibility notes

* All candidate streams are generated by seeded xoshiro256** generators. Counts of candidates, prefilter
  rejections, Miller-Rabin calls, and exponentiations are therefore identical on every platform; timings are not.
* In comparisons of prefilters and generation strategies, the Miller-Rabin bases are derived from the candidate so
  that all methods perform identical exponentiations. The complete generators (`gen_prime`,
  `generate_rsa_primes_fips`; `generate_provable_prime` needs no bases) draw their bases independently of the
  candidate, as required by the error bound. Use `SystemRandom` for real keys.
* The confirmatory OpenSSL experiment followed `docs/confirmatory_protocol_EN.txt`, fixed before data collection.
  The confirmatory comparison of V0-V3 at 2048 and 3072 bits is specified in `docs/protocol_V0-V3_2048_3072_EN.txt`
  (fixed before data collection; data not yet collected).
* The Python prototype was used for correctness checks and model validation; its timings include interpreter
  overhead and are not used for performance claims.
